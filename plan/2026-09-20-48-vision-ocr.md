# Plan: record the conclusion, and stop click_text dead-ending on a misread

## The approved decisions, carried over

1. **Tesseract stays.** The floor must be model-independent — offline, no
   account, no API key, no model choice — because both repos expose MCP servers
   and the model belongs to the caller. Vision models are disqualified by the
   0.1–110 word-height spread across six models, not by a ranking: `click_text`
   clicks a box centre with no verification, so a one-word-height error lands on
   the next row *and reports success*. `glm-ocr` reads better but cannot take a
   full frame (~27 s tiled against tesseract's 4.19 s). Recorded, not
   re-measured — a campaign would refine numbers that cannot change this.

2. **The text-quality complaint is answered by #58**, which landed a `screenshot`
   tool. A vision-capable caller now looks at the pixels with its own model and
   skips our OCR entirely. That is the honest fix, rather than replacing the
   floor for everyone.

3. **The real defect is recall, not accuracy.** `_find_phrase` (`tools.py:2320`)
   scores runs by `hits = sum(1 for w in wanted if w in text)` — substring
   containment. `"window" in "wordow"` is `False`, so the caller is told to go
   and `read_screen`, a full round trip to discover a word they already guessed
   right. It does **not** misclick; the refusal is honest. The fix must not turn
   a recall problem into an accuracy problem.

4. **A similarity cutoff is rejected on measurement.** True positives span
   0.667–0.889 and false ones 0.600–0.923; `close`/`c1ose` and `close`/`clone`
   both score **0.800**, and `delete`/`deleted` scores 0.923 — higher than every
   true positive. Any cutoff recovering `window` also matches `delete` against
   `deleted`. Recorded in the spec so it is not proposed again.

5. **Chosen: a confusable-character map (2a) plus naming the near miss (2b).**
   The map forgives only the substitutions tesseract actually makes, measured at
   5/11 recovered with **0/14** false collisions. The near miss is *reported,
   never clicked*, which is `keys.py:152`'s existing "did you mean" idiom
   (`difflib.get_close_matches`, `cutoff=0.72`), already pinned by
   `test_a_near_miss_is_offered_the_real_name`.

## One consequence the spec did not spell out, decided here

`_find_phrase` has **two** callers: `_tool_click_text` (2420) and the text branch
of `wait_for` (3529). Step 2a therefore changes `wait_for` as well, and that is
**deliberate and desirable**: `wait_for(text="Settings")` against a screen
tesseract reads as `Settinqs` polls until it times out today, for the identical
root cause. One guard in the shared function is the smaller diff and the honest
fix; patching only `click_text` would leave the sibling caller broken.

Step 2b is **not** extended to `wait_for`'s timeout message in this issue. The
spec scoped the near miss to `click_text`'s refusal, and `wait_for` would need
the last polled `words` threaded to the timeout path — a separate change with
its own failure modes. Noted as a follow-up, not smuggled in.

## Steps

1. **`tools.py`, module level**: add `OCR_CONFUSABLES` and `_ocr_fold(s)`.
   The map is `1→l`, `0→o`, `5→s`, `8→b`, `q→g`, `|→l`, `!→l` via
   `str.maketrans`, then `rn→m` on the result. Case-folded first.
   A comment records that `rn→m` is the first rule to drop if anything ever
   collides, because it is the only one that can merge two real words
   (`corner`/`comer`).
   → verify by a unit test over the spec's two tables: all 11 misread pairs
   fold equal or are left for step 2b, and **all 14** must-not-match pairs
   still fold unequal.

2. **`tools.py:2320` `_find_phrase`**: widen the hit test only. The line
   `hits = sum(1 for w in wanted if w in text)` becomes a check that tries
   containment first and falls back to `_ocr_fold`-ed containment. Nothing else
   in the function changes — not `_required_hits`, not the span scan, not the
   tightest-run preference.
   → verify by the existing `test_compose.py` matching tests passing **unedited**
   (429, 448, 456, 461, 464), which are the precision tests this must not break.

3. **`tools.py`, module level**: add `_nearest_word(words, query) -> dict | None`.
   Uses `difflib.get_close_matches` with `cutoff=0.72`, the same cutoff
   `keys.py:_suggest` uses, over the OCR tokens. Returns the word dict so the
   caller has its box, or None.
   → verify by a unit test: returns `wordow` for `window`, returns None when
   nothing is close.

4. **`tools.py:2420` `_tool_click_text`**: on the `point is None` branch only,
   call `_nearest_word` and, when it finds one, name it and its coordinates
   instead of the current "read the screen first" advice. When it finds nothing,
   the message is unchanged.
   → verify by a unit test asserting the near miss appears in the refusal **and
   that no pointer event is dispatched** — the same shape as #58's "no capture
   subprocess is spawned", and for the same reason: a message-level assertion
   alone would pass on an implementation that clicked first.

5. **Tests** in `tests/test_matching.py` (where the matching tests live) for
   steps 1–4, plus one asserting `wait_for(text)` now succeeds on a folded
   match, which is the shared-caller consequence decided above.
   → verify by the full suite.

6. `nix flake check`.
   → verify by `all checks passed!`, run in the sandbox rather than trusting a
   local green. **31 tests fail on this machine** (keys/scroll/dispatch) and do
   so identically on a clean tree; they are environmental and the sandbox is the
   authority.

7. **Comment on #48** recording decision 1 — the conclusion, the spread, why the
   floor must be model-independent, and that #58 answers the text-quality half.
   Then close the issue.
   → verify by the comment posted and the issue closed with a state reason.

## Rollback

`git revert` the implementation commit. `_find_phrase` returns to pure
containment, `click_text` to its old refusal text. No state, no migration, no
config, no schema change — the tool signatures are untouched, so a revert
restores exactly today's behaviour. The #48 comment stands on its own and would
not need reverting.
