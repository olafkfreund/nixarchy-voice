# Plan: name a window and the tool finds it

## The approved decisions, in full

Implementable without opening the intent or the spec.

**The problem, measured.** `read_screen`, `click_text`, `scroll` and `wait_for`
accept only `"screen"`, `"activewindow"` or a literal `address:0x…`. Verified
on the live system:

```
_target_geometry('class:google-chrome')
  -> no window with address 'class:google-chrome' — call hypr_query(clients) for current addresses
_target_geometry('chrome')
  -> no window with address 'chrome' — ...
```

So "read my email window" costs a `hypr_query(clients)` — 1942 characters,
~485 tokens — as **one model turn**, then the real call as **a second**. Two
turns at 1.5–7.6 s each for a lookup the code does in 13 ms, and the refusal
above instructs the model to spend the first one.

`send_shortcut` is already the exception: it passes the selector to Hyprland,
which resolves `class:chromium` itself.

Decisions carried over:

1. One resolver, `_resolve_window`, replacing the two near-identical ones.
2. It handles: active-window words, `address:`/bare hex, `class:`/`title:`
   selectors, and otherwise a ranked name.
3. Ranking, highest first: exact `class` → `class` prefix →
   `class`/`initialClass` substring → `title`/`initialTitle` substring.
   `initialTitle` counts as much as `title`; ties break to `focusHistoryID`
   ascending.
4. **Equal top scores are a question, not a guess** — return no window and name
   the candidates. Equal, not close: class beats title, so a browser and a
   terminal showing `chrome-flags.conf` is not a tie.
5. `_window_matches` becomes "this client scores above zero", so there is one
   definition of what a name matches.
6. No fuzzy-matching dependency.
7. The `hypr_query(clients)` advice comes out of the refusals.

## Steps

**1. `tools.py`: `_rank_windows(clients, name) -> list[tuple[float, dict]]`,
best first.** A module function, not a method — it needs no executor and that
makes it directly testable.

Score per the ordering above. Drop zero scores. Sort by score descending then
`focusHistoryID` ascending, so the tie-break is in the sort rather than in the
caller.
→ verify by: tests 1, 2, 3.

**2. `tools.py`: `_window_matches` delegates to it.**
`tools.py:451-461`. Becomes `bool(_rank_windows([client], hint))`. Keep the
docstring's `initialTitle` explanation — it records why a web app needs it, and
that reason now lives in the scorer.
→ verify by: test 8, plus the existing `_await_new_window` and `wait_for` tests
unchanged.

**3. `tools.py`: `_resolve_window(target) -> tuple[dict | None, str | None]`.**
Returns `(client, error)`. Order: active-window words → `address:`/bare hex →
`class:` / `title:` → ranked name.

**It does not apply the visible-workspace guard.** `_target_geometry` currently
does (`tools.py:2180-2185`) and `_window_geometry` does not — `scroll` checks
separately at `tools.py:2999` with a different message ("nothing to scroll"
against "nothing to read"). Folding the guard in would flatten two accurate
messages into one vague one, so it stays with the callers.

Its refusals must not name `hypr_query`.
→ verify by: tests 4, 5, 6, 9.

**4. `tools.py`: both existing resolvers become thin.**
`_target_geometry` (`tools.py:2145-2190`) keeps the `"screen"` branch, the
visibility guard and the geometry string, and calls `_resolve_window` for the
rest. `_window_geometry` (`tools.py:2951-2966`) becomes a call plus its
"nothing is open" case.

By-name targeting reaches `read_screen`, `click_text`, `scroll` and `wait_for`
from this one change, because #26 already routed the first three through
`_target_geometry`.
→ verify by: test 7 — every existing test for those four tools passes
untouched.

**5. `tools.py`: schema descriptions.**
`tools.py:818`, `858`, `953`, `984` all say `"address:0x..."`. They become
name-or-address, and say a name is preferred because it costs no lookup:
`"the window: a name like \"chrome\" or \"email\", \"activewindow\", or an
address from hypr_query. A name is resolved here — you do not need to query
first."`

That last sentence is the point of the whole chain, so it is worth being
explicit rather than hoping the model infers it.
→ verify by: test 10.

**6. `capabilities.py`: nothing.** Tool descriptions come from
`TOOL_SCHEMAS`. Listed so the absence is a decision.

## Tests

Plain `unittest`, `Executor._shell` / `_query_json` as the seam, per
`tests/test_reach.py:44-64`.

A shared fixture of clients used by most of these: a `google-chrome` window
titled "Issues · olafkfreund/Factory" on workspace 4, a second `google-chrome`
titled "Gmail" on workspace 2, and a `foot` terminal titled
"chrome-flags.conf" on workspace 1.

1. **Exact class beats everything.** `"google-chrome"` ranks both browsers
   above the terminal.
2. **Class beats title.** `"chrome"` ranks the browsers above the terminal
   titled `chrome-flags.conf` — and the terminal is not a candidate for a tie.
3. **`initialTitle` counts as much as `title`.** The web-app case the existing
   docstring describes: `initialTitle` "www.bbc.com_/news", `title` a headline.
   `"bbc"` finds it.
4. **A name resolves in one call.** `read_screen(target="gmail")` produces that
   window's geometry, with one `clients` query and no error. This is the two
   turns becoming one, and it is the test that represents the issue.
5. **A real tie is refused and names the candidates.** `"google-chrome"`
   against the two browsers → no window, an error containing both titles and
   both workspaces, and **no capture attempted** (`shell.assert_not_called()`,
   the `tests/test_compose.py:149-160` pattern).
6. ~~**Ties break to the focused window.**~~ **Deviation, found by writing
   this test.** The spec asks for both "ties break toward the focused window"
   and "equal top scores are a question", and those collide exactly when two
   equal-scoring windows exist and one is focused. The question wins: choosing
   the focused window *because* it is focused is the silent pick the ambiguity
   rule exists to prevent, and `activewindow` already means "the one I am
   looking at". So `focusHistoryID` orders the candidate list and does not
   select. Replaced by two tests — a clear best match resolves without asking
   (which is what test 6 was really for: without it, refusing everything would
   pass test 5), and focus names the focused candidate first without choosing
   it.
7. **Nothing regressed on the old forms.** `activewindow`, `address:0x…` and a
   bare `0x…` behave exactly as before, across all four tools.
8. **`wait_for(window_gone)` and the widened matcher.** The spec's named
   behaviour change: a name that matched nothing may now match, so
   `window_gone` may report "still open" where it said "gone". Assert the new
   behaviour deliberately rather than discover it.
9. **Explicit selectors are exact.** `title:chrome` does not find a window of
   class `chrome`, and `class:foot` does not find one merely titled "foot".
10. **No refusal sends the model to `hypr_query`.** Search every error string
    `_resolve_window` can produce. This is the round trip the chain exists to
    remove, and leaving it in as advice would keep the model paying it.

Commands and expected results:

```
nix develop -c python3 -m unittest discover -s tests   # green; 640 before
nix flake check                                        # green
nix develop -c python3 -m omarchy_voice verify-gate    # exit 0
```

**Live check on the desktop**, which is the claim in one line:
`read_screen(target="chrome")` returns text, in one call, having issued one
`clients` query.

## Deviations found by running it on the real desktop

The fixture in the tests was too tidy. Two things only showed up live, both
now pinned by their own tests:

1. **The "class starts with the name" tier had to go.** Omarchy web apps take
   a class like `chrome-ejhkdoiecgkmdpomoahkdihbcldkgjci-Default`, which
   *starts with* "chrome" and so outranked the actual `google-chrome`, which
   only contains it. Five web apps above the browser. A prefix is only more
   meaningful than a substring when the class is a word rather than a
   generated id. Scoring is now exact class (4.0) → class substring (2.0) →
   title substring (1.0).
2. **The "Open now:" list in a failed match ran to 353 characters** of
   extension hashes — charged against the turn budget every time a name
   missed. It now shows a web app by its title and caps at eight names: 130
   characters on the same desktop.

## Rollback

One branch, `perf/27-matching`. No state, no dependency, no packaging change:
`git revert` the merge and restart the daemon.

The risky step is 4, because it touches the resolution path for four tools at
once. It is ordered last of the code steps for that reason, and test 7 is the
gate on it: if the existing tests for those four do not pass untouched, the
refactor is wrong regardless of what the new tests say.

Steps 1–3 are additive — new functions nothing calls yet — so reverting step 4
alone leaves a working tree with by-name resolution present but unused, which
is a safe place to stop.
