# Plan: wake on the compositor saying so

## The approved decisions, in full

Implementable without opening the intent or the spec.

**The measurement.** Launching a real window, five runs on this host:
`socket2` `openwindow` arrives at **75 ms**, today's `sleep(0.15)` poll notices
at **164 ms**, the same poll at `sleep(0.03)` notices at **94 ms**. One
`hyprctl -j clients` costs 13 ms.

So the listener buys 91 ms over today and 19 ms over one changed constant,
against a model turn of 1.5–7.6 s. **The justification is not the 91 ms.** It
is that `wait_for` can run for 25 s and polling that burns a core throughout,
while a blocked socket read costs nothing. The 91 ms is a bonus.

**The decision everything follows from: the listener never parses a payload.**
Only the text before `>>` is read. This is the approved "an event means
recheck, never it happened" constraint, and it removes every protocol hazard at
once — captured from the live compositor:

```
openwindow>>5d811f0beb30,11,foot,ev,probe,with,commas
```

- Titles carry **unescaped commas**, so the payload cannot be split on `,`.
  Irrelevant: titles are never read.
- Event addresses have **no `0x` prefix** where `hyprctl`'s do. Irrelevant:
  addresses are never read.
- Event data is **truncated at 1024 bytes** (`EventManager.cpp:128`).
  Irrelevant: no event *name* approaches that.
- A `hyprctl reload` has **no cached state to invalidate**, because nothing is
  cached.

**The failure mode that survives**, verified in the source this Hyprland was
built from:

```
EventManager.cpp:169   const size_t MAX_QUEUED_EVENTS = 64;
EventManager.cpp:175   "Socket2 fd {} overflowed event queue, removing"
```

A slow reader is dropped and not told. There are no sequence numbers, so a gap
is undetectable from inside. Hence: the listener thread does nothing but read.

Carried over:

1. Listener in its own module, one per process, created lazily, shared.
2. It sets a `threading.Event` and nothing else — no matching, no querying, no
   callbacks into `Executor`.
3. Waiters use `event.wait(gap)`, so they wake on event or timeout, whichever
   is first.
4. `gap` backs off: **30 ms for the first second, then 150 ms.**
5. `hyprctl` stays authoritative for every consequential read.
6. Connect before taking the baseline; check the condition before sleeping.
7. Never `Executor._lock` from the listener thread.
8. No socket, EOF or error → poll only, no error surfaced to the model.

## Steps

**1. New `src/omarchy_voice/hypr_events.py`.**
`Listener` with `wake: threading.Event`, `start()`, `stop()`, `available: bool`.

- Socket path from `$XDG_RUNTIME_DIR/hypr/$HYPRLAND_INSTANCE_SIGNATURE/.socket2.sock`
  (the variable is set in this session; fall back to a glob of
  `$XDG_RUNTIME_DIR/hypr/*/.socket2.sock` and take the newest, because
  `omarchy-voice mcp` can be started from a context that lacks it).
- A daemon thread: `recv`, buffer, split on `\n`, keep the trailing partial
  line, and for each complete line take `line.split(b">>", 1)[0]` and `wake.set()`
  if it is in `WAKE_EVENTS`.
- `WAKE_EVENTS`: `openwindow`, `closewindow`, `movewindowv2`, `windowtitle`,
  `windowtitlev2`, `activewindow`, `activewindowv2`, `workspace`, `focusedmon`,
  `fullscreen`, `changefloatingmode`. Over-waking is free; the waiter re-checks
  and sleeps again.
- EOF or error → `available = False`, reconnect with backoff, keep the thread.
- `listener()` module function returning the lazily-created singleton, and
  returning one whose `available` is False when there is no socket.

Nothing in this module imports `tools`. It is a socket and an Event.
→ verify by: tests 1, 2, 3.

**2. `tools.py`: a `_wait_tick` helper.**
`_wait_tick(waker, elapsed) -> None` — sleep until the next check: 30 ms while
`elapsed < 1.0`, else 150 ms, waiting on the listener's Event when one is
available and falling back to `time.sleep` when it is not. Clears the Event
before returning so the next tick does not see a stale set.

One helper, because steps 3 and 4 are otherwise the same five lines twice, and
that is how the existing wait loops drifted apart in the first place.
→ verify by: tests 4 and 5.

**3. `tools.py`: `_await_new_window` waits on it.**
`tools.py:2217-2231`. Replace `time.sleep(0.15)` with `_wait_tick`, and
**check before the first sleep** — the current loop sleeps 150 ms before
looking, so a window that is already mapped when the call starts costs 150 ms
for nothing.
→ verify by: tests 6 and 7.

**4. `tools.py`: `wait_for`'s window branches wait on it.**
`tools.py:3054-3070`. `what="window"` and `what="window_gone"` use
`_wait_tick`.

**`what="text"` deliberately does not.** No compositor event fires when words
appear on a page, so the Event would never be set and the wait would run at the
backoff interval regardless — the appearance of an improvement with none of it.
Text keeps its `WAIT_POLL_TEXT` pacing, which is set by OCR cost, not by
compositor latency. Same reason `_await_paint` (#26) is untouched: it waits on
pixels.
→ verify by: test 8.

**5. `cli.py`: `doctor` reports the listener.**
One line: connected, or not and why. The spec's named risk is that a silent
disconnect degrades to the poll and nobody finds out. `doctor` is where that
becomes visible.
→ verify by: run it.

**6. Lifecycle.** The daemon stops the listener on shutdown, beside the other
teardown in `local_engine`/`realtime`. A short-lived `omarchy-voice say` may
never create one; that is fine, it is lazy.
→ verify by: no thread left behind after the suite, which `unittest` will
complain about if a non-daemon thread lingers.

## Tests

New `tests/test_hypr_events.py`, plus cases in the existing wait tests. Plain
`unittest`; no compositor — the listener is fed from a socketpair.

1. **Only the event name is read.** Feed
   `openwindow>>5d811f0beb30,11,foot,ev,probe,with,commas\n` and assert the
   Event is set and that nothing on the Listener holds any part of the payload.
   The comma-laden title is the real captured case.
2. **Partial reads are buffered.** Deliver `openwin`, then
   `dow>>a,b\nclosewi`, then `ndow>>c\n`; two wakes, nothing lost.
3. **An unknown event does not wake.** `monitoradded>>DP-9` leaves the Event
   clear, so the wake list is an allowlist rather than "anything".
4. **The gap backs off.** With no listener, ticks are ~30 ms for the first
   second and ~150 ms after; asserted on a fake clock, counting sleeps.
5. **A wake short-circuits the tick.** With a listener, setting the Event
   returns from `_wait_tick` without waiting out the gap.
6. **A window already present returns without sleeping at all.** The
   check-before-sleep fix; fails against today's code.
7. **`_await_new_window` still behaves identically otherwise** — the hint
   matching, the `focusHistoryID` sort and the unclassed-dialog skip are
   untouched, so the existing tests pass unchanged.
8. **`wait_for(text=…)` does not wait on the listener.** Asserted, not assumed:
   a test that sets the Event and shows the text branch still paced by
   `WAIT_POLL_TEXT`. This is the one place a plausible-looking change would be
   silently useless.
9. **No socket is not an error.** With `XDG_RUNTIME_DIR` pointed at an empty
   directory, `listener().available` is False, waits still work, and nothing
   reaches the model. This is also how the nix sandbox runs.
10. **EOF reconnects** and a waiter running across it still completes.
11. **No deadlock**: a test holds `Executor._lock` while a waiter waits and the
    listener delivers.

Commands and expected results:

```
nix develop -c python3 -m unittest discover -s tests   # green; 640 before
nix flake check                                        # green, no compositor
nix develop -c python3 -m omarchy_voice verify-gate    # exit 0
nix develop -c python3 -m omarchy_voice doctor         # names the listener
```

**The measurement that justifies the change**, repeated as it was taken: launch
a real window five times and record detection latency, before and after. Expect
~164 ms → ~75 ms. If it does not reproduce, the listener is not working and the
poll is quietly covering for it — which is exactly the failure this is most
likely to have.

## Rollback

One branch, `perf/28-waiting`. Nothing outside the repo changes, no state, no
new dependency, no packaging change: `git revert` the merge and restart.

Steps are ordered so the listener is additive. Steps 3 and 4 fall back to the
poll if `listener()` never becomes available, so reverting step 1 alone leaves
working code — the waits just run at the backoff interval. The cheap partial
rollback, if the listener misbehaves in use, is to make `listener()` always
report unavailable: that is the "tighter poll and no listener" alternative the
spec recorded, reached without removing anything.
