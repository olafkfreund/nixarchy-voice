# Spec: voice installs through nixarchy's plugin option, credits its voice, and checks readiness at runtime

## Design

### New ids: `olafkfreund.voice-indicator` and `olafkfreund.voice-orb`

The owner decided on the `olafkfreund.` prefix. Every reference moves at once:

| Where | From | To |
|---|---|---|
| `plugin/voice.indicator/` directory and `manifest.json` `id` | `voice.indicator` | `olafkfreund.voice-indicator` |
| `plugin/voice.orb/` directory and `manifest.json` `id` | `voice.orb` | `olafkfreund.voice-orb` |
| `plugin/…/VoiceIndicator.qml` `moduleName` | `voice.indicator` | `olafkfreund.voice-indicator` |
| the package's `share/omarchy-voice/plugins/<id>` | old dirs | new dirs |
| `nix/hm-module.nix:105,163-168`, `README.md:142,800,820,847`, the comment at `src/omarchy_voice/feedback.py:27` | old ids | new ids |

The directory name equals the id, which is what `omarchy-plugin-validate`
expects.

### Registration: nixarchy's option when it exists, files otherwise

`nix/hm-module.nix` replaces the two `xdg.configFile` entries (`:162-169`):

```nix
(lib.optionalAttrs (options ? programs.nixarchy.plugins) {
  programs.nixarchy.plugins = lib.mkMerge [
    (lib.mkIf cfg.barWidget { "olafkfreund.voice-indicator".src = "${plugins}/olafkfreund.voice-indicator"; })
    (lib.mkIf cfg.orb       { "olafkfreund.voice-orb".src       = "${plugins}/olafkfreund.voice-orb"; })
  ];
})
```

It falls back to today's `xdg.configFile` links (at the new ids) when the
option doesn't exist, for Omarchy without nixarchy. The guard is
`options ? programs.nixarchy.plugins`, the same test ai-mirror's module uses,
and it evaluates without the nixarchy module present.

Through nixarchy's option the plugins get its build-time validation and its
reconcile, which removes a plugin dropped from the config. They are installed
but **not enabled**: enabling stays nixarchy's decision (nixarchy#774 makes
voice an opt-in setup) or the user's.

### Migration for existing homes

Home Manager removes the old links (`omarchy/plugins/voice.indicator` and
`voice.orb`) on its own, because they were Home Manager-managed files that are
no longer declared. What doesn't migrate itself is **`shell.json`**, which
still names the old ids in `bar.layout` and `plugins[]`. An id with no plugin
behind it shows nothing, and the new one isn't enabled.

Fix: a one-time hook in `~/.config/omarchy/hooks/post-boot.d/voice-migrate-ids`,
generated by the module. It is the same mechanism nixarchy uses for its default
plugins: it runs after the shell is up, and it writes through the shell's own
`omarchy plugin` commands, never `shell.json` directly. For each old id that
`omarchy-plugin-list --json` reports **enabled**, it runs
`omarchy plugin disable <old>` and then `omarchy plugin enable <new> right` (or
`plugins[]` for the orb, which is a panel). It then writes
`~/.local/state/omarchy-voice/ids-migrated`. The marker is written only after
every step succeeds, so a failure retries at the next login. An old id that
was *off* stays off under its new name.

### Crediting "Jenny (Dioco)"

- **Per-voice licence metadata.** `nix/piper-voice.nix:23` stops giving every
  voice `lib.licenses.mit`. `mkVoice` takes `license`, `attribution` and
  `modelCardHash`, and each voice declares its own from its model card:
  - **`en_GB-jenny_dioco-medium`:** the model is MIT, and its dataset requires
    attribution in any interface generating speech, as "Jenny (Dioco)". So
    `attribution = "Jenny (Dioco)"`, with a licence that names both.
  - **`en_GB-cori-high`:** public-domain dataset, per its model card, with no
    attribution requirement.
  - **`en_US-lessac-high`:** the implementer reads its `MODEL_CARD` and records
    what it says. The spec doesn't guess. If the card is unclear, the voice is
    marked with its card URL, and the question goes on the issue.
- **Model cards ship.** `mkVoice` also fetches `MODEL_CARD` (hash-pinned) into
  `$out`, beside the `.onnx` and `.onnx.json`.
- **Where the credit is visible** (the owner decided on these three places):
  - **`omarchy-voice doctor`,** under `speech`: `voice en_GB-jenny_dioco-medium — voice: Jenny (Dioco)`.
    The text comes from the package's `passthru.attribution` through an env
    var the wrapper sets, so it can't drift from the Nix metadata.
  - **the indicator's tooltip or about text:** the same line;
  - **`README.md`:** a "Voices and credits" line for each shipped voice.

### Readiness at runtime, not at evaluation

- **Removed:** the eval-time warning `no API key set` (`nix/hm-module.nix:303-307`).
  It fires on every rebuild, even when the Claude backend needs no key at all.
- **At startup,** much of this already exists. The local engine
  (`local_engine.py:602-611`) runs `check_ready()`, prints each hard problem to
  the journal, sets the indicator to `unconfigured`, and exits 0 so the unit
  doesn't flap. The change is small:
  - the implementer confirms the **realtime** engine's start path does the same
    readiness check, and brings it into line if it doesn't;
  - both send **one** desktop notification, "voice has no backend: run
    `omarchy-voice doctor`", instead of only setting the indicator state;
  - this is what replaces the eval-time warning, which is the real change.
- The **PipeWire warning stays.** It reads `osConfig`, not a secret, and it is
  true at evaluation.
- **No secret is read at evaluation** (intent constraint). The module only
  passes key file *paths* along, as today.

## Alternatives rejected

- **`nixarchy.voice-*` ids:** the owner chose `olafkfreund.`.
- **Keeping the old ids with an alias:** the Omarchy shell has no id aliasing.
  Two manifests for one plugin would be refused as a duplicate by validation.
- **Migrating `shell.json` from Home Manager activation:** activation runs
  while the shell may be live, and the shell rewrites that file from memory.
  nixarchy found this for #766, which is why its default plugins use a
  post-boot hook through the shell's own writer.
- **Speaking the credit at first run:** the owner decided on doctor, the plugin
  and the README.

## Risks

- **A user who scripted `omarchy bar put voice.indicator`** must use the new id.
  The README and the release notes say so.
- **If `omarchy plugin disable|enable` changes upstream,** the hook fails.
  Because the marker is only written on success, it retries and logs to the
  journal with `systemd-cat`, rather than silently leaving the widget off.
- **The model card download** adds a fetch per voice. The files are small, but
  one more pinned URL can change, and `fetchurl`'s hash catches that.

`nix flake check` (`check.yml`):

| Check | How it goes red today |
|---|---|

| a pytest: `doctor` output contains `Jenny (Dioco)` when the attribution env var is set | doctor prints no credit |
| a pytest: daemon start with no backend ready sends one "no backend" notification and exits 0, for **both** engines | today it only sets the indicator state, and the realtime path is unverified |
| a module eval with no key set produces **no** warning | today it warns |
| the migration hook, as a unit test with `omarchy-plugin-*` stubbed: an enabled old id becomes disabled and the new one enabled, the marker is written, the second run does nothing, and an off old id isn't enabled | there is no hook |

The existing `checks.<system>.unit` gains the pytests. The module and package
checks are new flake checks, and CI runs all of them through
`nix flake check`, so there's no workflow edit.
