# Spec: A published page, a real demo, and a story a new user can follow

The intent was approved without answers, so every recommendation stands:

- **Voice:** Piper.
- **Requests:** typed turns shown as captions, plus an optional short real
  spoken clip.
- **Page:** one static HTML page, published by a Pages workflow.
- **Video:** in the repo if under ~8 MB, otherwise a release asset.
- **nixarchy:** pin bump, "opt-in", and a measured size, filed as
  **nixarchy#1022**.

## Design

### 1. The demo: recorded on razer, driven from p620

**Where it's recorded.** razer (`eDP-1`, 1920x1080, scale 1). Its Oma chain
works:
- whisper.cpp → Claude Code on the user's plan → Piper "Jenny";
- no ElevenLabs key;
- desktop control off.

That's the path a new user without extra keys gets.

**How it's recorded.** A new `demo/` folder in this repo, modelled on nixarchy's
`tests/demo/screencast/` (#930) and reusing its lessons, not its code (that
harness is nixarchy's hero video):

- `demo/shots.toml` is the shot list, as data. Each beat has:
  - `action`: what the driver does;
  - `hold`: seconds to wait;
  - `expect`: text that must be readable on screen during the beat;
  - `caption`: what the viewer reads.

  One file drives the take, the check and the captions, so they can't drift
  apart (nixarchy's rule).
- `demo/rz` runs a command on razer with its Hyprland session environment.
  This is ai-mirror's `demo/rz` pattern: a non-login ssh shell has none of
  that environment.
- `demo/record` does the take:
  - on razer: `gpu-screen-recorder -w eDP-1 -f 30 -a default_output -c mp4`,
    so the video carries Oma's voice from the speaker output;
  - it then drives the beats and stops the recorder;
  - **fallback:** if the pre-flight test shows frozen or identical frames (as
    `wl-screenrec` did on razer, per ai-mirror's `demo/README.md`), it uses
    `grim -t jpeg` frames plus `pw-record` of
    `alsa_output….analog-stereo.monitor`, joined with ffmpeg.
- `demo/verify`:
  - samples the **raw** master at each beat's observed time;
  - OCRs it (tesseract is on razer) and requires `expect` to be there;
  - refuses a file that already has captions, so a caption can't satisfy its
    own check (nixarchy's rule);
  - checks the audio track is not silent.
- `demo/edit` produces the outputs from the one master:
  - `docs/media/oma-demo.mp4`: 16:9, 1280x720, H.264 plus AAC, captions
    burned in, `+faststart`, target under 8 MB;
  - `docs/media/oma-demo.jpg`: the poster frame;
  - stills (next section);
  - the **silent 16:10 GIF for nixarchy**: crop 1728x1080 centred, then
    nixarchy's `encode-gif.sh` settings (4 fps, 900 px, palette capped at 96
    colours), under 1 MB.

**Preparation.** `demo/prep` refuses rather than tidies, as nixarchy's does:
- it lists open windows and pending notifications, and stops if any exist;
- it records the theme (`omarchy-theme-current`, now Osaka Jade), the
  wallpaper and Do Not Disturb;
- it switches to the default Tokyo Night for the take, so the media matches
  nixarchy's backdrop;
- it turns Do Not Disturb on, except for Oma's own notifications;
- it works on an empty workspace;
- **herdr stays out of shot**, because its panel lists real sessions
  (nixarchy's `docs/AGENTS.md`);
- **restore** puts back the theme, wallpaper, DND and workspaces, deletes the
  `demo-*` actions and routine units, and re-reads the live state to confirm.

**The beats.** Everything real, on razer. The only thing typed rather than
spoken is the request, shown as a caption. Each item gives what is said or
done, what is shown, and what `expect` checks for.

1. **"Oma"** is toggled on. The bar widget shows her listening. *expect:* the
   widget state.
2. *"Make an action called demo-focus: switch to workspace 5, open the
   nixarchy-voice page in its own window, and run git status in my demo
   repo."*
   - Oma reads the recipe back aloud and holds it.
   - *expect:* the notification with the readback.
3. *Confirm.* The action is saved. *expect:* `saved demo-focus`, or the menu
   row appearing.
4. **Menu:** Voice ▸ Actions ▸ demo-focus ▸ Run.
   - The workspace switches, the page opens, and `git status` runs, pasted
     into Oma's own `Oma` tmux session.
   - *expect:* `On branch` in the terminal.
5. *"Run the tests in my demo repo."*
   - The demo repo has a test that fails on purpose.
   - Oma says the tests failed, with the exit status. That's #161's reporting.
   - *expect:* `exit 1`.
6. *"How long has this machine been up?"* A spoken answer from `/proc`
   (#162). *expect:* `up`.
7. **A routine:** `demo-hello`, set to fire a minute ahead, is enabled from
   the menu (*Routine ✓*).
   - Its notification arrives.
   - *expect:* the notification title `Oma: demo-hello`.
8. **End card:** the page URL.

The demo repo is `/tmp/oma-demo` on razer: `git init`, one file, and a
`Makefile` whose `test` target exits 1. It's created by `prep` and removed by
`restore`. No real repository or mail appears.

**The optional real-speech clip.** If you're at razer, `demo/record --live`
records one beat with the microphone instead of `listen say`. It's shown on the
page as a separate short clip. If you're not there, it's skipped.

  kept: the tokens, the light/dark themes, and the Chivo and IBM Plex fonts.
  Its content is replaced:
  - a hero with the video (poster, `<video controls preload="none">`);
  - what Oma is, next to Voxtype;

  - what it costs;
  - the safety model (deny, confirm, approve-once, the recording guard);
  - screenshots;
  - links to the README for the full reference.
- **Stale 0.3 claims go:** "8 tools", "113 unit tests", "Omarchy 4.0.1",
  `./install.sh`, "v0.3 honesty". Numbers that change (tool count, test count)
  are left out rather than hard-coded.
- **Fonts:** the Google Fonts link stays. It's the only external request,
  already there, and it degrades to the system fonts.
- **`.github/workflows/pages.yml`**:
  - on push to `main` touching `docs/**`, plus `workflow_dispatch`;
  - `actions/configure-pages` → `actions/upload-pages-artifact` (path
    `docs`) → `actions/deploy-pages`;
  - `permissions: pages: write, id-token: write`.

  It's a new CI file, flagged in the PR for your review. It doesn't alter the
  existing `check.yml` gate.
- **Size:** everything under `docs/media` is kept under 12 MB in total. If
  the mp4 goes over 8 MB, it becomes a release asset and the page links it.

### 4. The user story

One story, at two lengths:

- **README:** a new `## Getting started` section right after the opening
  paragraphs. It's about 60 lines, with the same six steps as the page:
  1. **Install:**
     - nixarchy users: the Omarchy menu's *Set up voice*, or
       `programs.nixarchy.voice.enable = true`;
     - everyone else: the Home Manager module (the existing Install snippet,
       linked).
  2. **Sign in:** Claude Code, on your plan. Whisper and Piper are local,
     and ElevenLabs is optional.
  3. **The key:** `SUPER + SHIFT + V`, or the bar widget. Listening starts
     off.
  4. **Say something:** three first sentences that work.
  5. **Your first action:** do it, then say "make that an action called …".
     Or use Voice ▸ New action…
  6. **Your first routine:** `omarchy-voice action enable morning-repo`, and
     where its result appears.
  7. **When it doesn't work:** `omarchy-voice doctor`, `omarchy-voice log`,
     and the confirm word.
- **Page:** the same steps, rendered with the screenshots. The page links to
  the README section rather than repeating the details.

## Alternatives rejected

- **Recording on p620:** a work desktop, with client sessions on screen.
- **Mocked screenshots or a staged take:** the intent forbids it, and #158's
  own live check showed how a real run surfaces real bugs.
- **Turning the recording guard off for the camera:** the demo shows actions
  instead.
- **Reusing nixarchy's harness code directly:** its shot list, acts and
  restore are built around nixarchy's plugins and its hero video. The ideas
  transfer; importing would couple the two repos' CI.
- **Jekyll or Markdown for the page:** a generator and theme for one page,
  and the existing HTML design would be lost.
- **ElevenLabs for the demo voice:** not what a keyless new user hears.
- **Keeping `docs/omarchy-voice.html` alongside `index.html`:** two pages that
  would drift. It's replaced, and the old URL path never served anyway.

## Risks

- **`gpu-screen-recorder` may not capture correctly on razer**, as
  `wl-screenrec` didn't. It's tested before the take; the `grim` plus
  `pw-record` fallback is specified.
- **Audio levels:** Piper through the speaker monitor may be quiet or clipped.
  `verify` checks the level; `edit` normalises the loudness.
- **Model non-determinism:** Oma's wording differs between takes. `expect`
  checks facts on screen (`exit 1`, `On branch`, `up`), not exact phrases.
  Captions show the request, not her reply.
- **Leakage on razer:** the notification centre, bar widgets and herdr.
  `prep` refuses on any window or notification, DND is on, and herdr stays out
  of shot. The final frames are reviewed by eye before publishing.
- **Repo growth:** capped at 12 MB, with the release-asset fallback.
- **The Pages workflow** is new CI and needs your review in the PR.
- **Restore fails mid-way** and leaves razer in Tokyo Night with demo units.
  `restore` is idempotent and re-runnable, and `prep` writes the starting
  state to a file first.
