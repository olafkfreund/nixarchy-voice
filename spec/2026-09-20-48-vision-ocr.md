# Spec: tesseract stays, and click_text stops dead-ending on a misread

The intent asked one question and identified a second defect while answering it.
This spec closes the first with a recorded conclusion and fixes the second.

- **The question.** Is there a model-independent screen reader better than
  tesseract? **No.** Recorded, not re-measured — see below.
- **The defect.** Bad OCR characters cost `click_text` *recall*, not accuracy.
  That is real, cheap to improve, and independent of the answer above.

## Part 1 — the conclusion, recorded rather than re-measured

Outcome 1 from the intent, taken without a further campaign. The reasoning is
architectural and the evidence needed for it is already in hand: the 0.1–110
word-height spread across six models. A campaign would refine numbers that
cannot change the conclusion.

The floor must be **model-independent** — offline, no account, no API key, no
model choice — because both repos expose MCP servers and the model belongs to
the caller. Against that bar:

- **Vision models**: disqualified as a floor by the spread, not by a ranking.
  `click_text` clicks a box centre with no verification, so a one-word-height
  error lands on the next row *and reports success*. Silently wrong on some
  users' machines and not others is worse than uniformly mediocre.
- **`glm-ocr`**: transcribes visibly better than tesseract, but cannot take a
  full frame (2560x1440 aborts on `token repeat limit reached`, resolution-driven
  and unaffected by `repeat_penalty`). Tiled, ~27 s against tesseract's 4.19 s.
  Better reader, worse floor.
- **Cloud**: not a candidate. A floor cannot require a network or upload the
  user's screen.

Tesseract's characters are poor, but its boxes are the same for everyone.

**The text-quality complaint is answered elsewhere, and already is:** #58 landed
a `screenshot` tool, so a vision-capable caller can now look at the pixels with
its own model and skip our OCR entirely. That is the honest fix for "OCR reads
`wordow`" — not replacing the floor for everyone.

## Part 2 — the click_text recall fallback

### The defect, precisely

`_find_phrase` (`tools.py:2320`) scores a run of words by
`hits = sum(1 for w in wanted if w in text)` — **substring containment**. When
tesseract reads `wordow`, `"window" in "wordow"` is `False`, the run falls under
`_required_hits`, and the caller is told "could not find 'window' on screen.
Read the screen first". That advice costs a full `read_screen` round trip to
discover a word the caller already guessed correctly.

Note what is *not* broken: it does not misclick. The refusal is honest. This is
a recall problem and the fix must not turn it into an accuracy problem.

### Rejected: a similarity threshold on the whole word

The obvious fix is to count a hit when `SequenceMatcher(...).ratio()` clears a
cutoff. **Measured, it cannot work.** The two distributions overlap almost
entirely:

| real misread (must match) | ratio | | distinct word (must NOT match) | ratio |
|---|---|---|---|---|
| `window` / `wordow` | 0.667 | | `reply` / `apply` | 0.600 |
| `close` / `c1ose` | 0.800 | | `close` / `clone` | **0.800** |
| `files` / `fi1es` | 0.800 | | `files` / `tiles` | **0.800** |
| `today` / `toaay` | 0.800 | | `cancel` / `cancer` | 0.833 |
| `issues` / `1ssues` | 0.833 | | `discard` / `discord` | 0.857 |
| `packaging` / `packaqing` | 0.889 | | `delete` / `deleted` | **0.923** |

True positives span 0.667–0.889; false ones span 0.600–0.923. `close`/`c1ose`
and `close`/`clone` are **the same number**. Any cutoff that recovers `window`
also matches `delete` against `deleted` — the exact silent-misclick failure the
intent names as worse than the defect being fixed. Recorded here so it is not
proposed again.

### Chosen: two changes, neither of which can misclick

**2a. Widen the hit test with a confusable-character map, not a similarity
score.** OCR errors are not random; they are a known substitution set. Normalise
both sides through `str.translate` (`1→l`, `0→o`, `5→s`, `8→b`, `q→g`, `|→l`,
`rn→m`) and compare exactly.

Measured on the same two sets: **recovers 5/11 real misreads with 0/14 false
collisions.** Clean separation, because it forgives only the substitutions
tesseract actually makes — `c1ose` normalises onto `close`, while `clone` never
does. Half the recall back at no precision cost and no round trip.

**2b. Name the near miss in the refusal.** For the other half (`wordow`,
`frade`, `searcn` — errors no substitution map catches), do not guess: say what
is actually there and let the caller decide.

> could not find `'window'` on screen. The closest text is `'wordow'` at
> 1240,880 — if that is what you meant, call click_text with that wording.

**This is the repo's existing idiom, not a new one.** `keys.py:152` already does
precisely this for an unknown key name: `difflib.get_close_matches(name, pool,
n=1, cutoff=0.72)`, offered as a "did you mean" **in the error message and never
acted on**, with `test_a_near_miss_is_offered_the_real_name` pinning it. Reusing
the pattern and its cutoff keeps one behaviour in the codebase rather than two.

The safety property is structural: the near miss is *reported*, never clicked.
`delete`/`deleted` confusion becomes a sentence the caller reads, not a pointer
event. Recall improves; the accuracy risk is zero by construction.

## Alternatives rejected

| Alternative | Why not |
|---|---|
| Replace tesseract with a vision model | The spread. Not model-independent. Part 1. |
| `glm-ocr` as the default reader | Cannot take a full frame; ~27 s tiled. |
| `glm-ocr` as an opt-in `read_screen` mode | Deferred, not rejected — open question 3. Out of scope here. |
| Similarity cutoff on whole words | Measured; distributions overlap. Above. |
| Auto-click the near miss | Converts an honest refusal into a silent misclick. The one outcome the intent calls worst. |
| Lower `MIN_OCR_CONFIDENCE` (45.0) | Admits more garbage tokens, which widens the misclick surface rather than recall for real words. |

## Risks

- **The confusable map is a fixed guess at tesseract's error set.** It is
  measured on 11 real pairs, which is a small sample. Mitigation: it can only
  ever *add* matches that exact containment missed, and it produced no false
  collisions in the negative set. If a collision is found later, the map shrinks.
- **`rn→m` is the one rule that can merge distinct words** (`corner`→`comer`).
  It is the classic OCR confusion and worth having, but it is the first rule to
  drop if anything collides.
- **The near-miss message quotes screen text back to the caller.** It must go
  through the same sensitive-window guard as any other read — it does, because
  `_ocr_words` is already behind `_capture_refused`, and the message is built
  from words that call already returned.

## Verification

- Unit tests on the two measured sets: every real misread in the table matches
  after 2a or is named by 2b; **every** word in the must-not-match column still
  fails to match.
- A test asserting the near miss is reported and **no pointer event is sent** —
  the same shape as #58's "no capture subprocess is spawned", and for the same
  reason: a message-level assertion would pass on an implementation that clicked
  first.
- `_required_hits` behaviour unchanged for clean OCR: existing `click_text`
  tests pass unedited.
- `nix flake check`.
- A comment on #48 recording Part 1, then close.

## Open questions carried forward

Question 3 from the intent — `glm-ocr` tiled as an opt-in `read_screen` mode for
offline users at ~27 s — is **not** settled here. It is a separate enhancement
and should be its own issue if wanted; #58's `screenshot` tool may have removed
most of the appetite for it.
