# Spec: the hold drops to 0.6 s, measured, and the detectors wait for a cut-off

Refs #138. Line numbers are from `main` at `be27af4` (v2.0.0, #80 merged
in PR #134), which is the base of `perf/138-end-of-turn`. The intent's
references are unchanged there.

The owner chose to build this now, before #80's trigger (4 or more fragment
endings in 50 `heard` lines) has fired. There is still no real turn at
0.8 s: 0 `TIMING` lines, 0 `hold=` values, and 0 `heard` lines since #72.
So this spec builds the one candidate that needs no data to be safe to try:
it is one default, and one config line rolls it back. The detectors are
specified far enough to be started on a trigger, and no further.

## Decisions on the intent's open questions

The intent was approved without answers to its open questions, so each one
is decided here with its reasoning. Any of them can be rejected at this
gate.

1. **The 0.6 s default ships first and alone. The default moves, not only
   this machine's `config.toml`.**
   - Why alone: it is the only candidate whose cost is known in advance
     (none: no dependency, no new code path) and whose failure is undone
     without a release. A detector in the same change would make any change
     in the fragment rate impossible to attribute to one of the two.
   - Why the default: a line in `~/.config/omarchy-voice/config.toml` is
     not reviewed, not versioned, and only reaches one host. The default is
     one reviewed line that reaches p620 and razer on the next rebuild, and
     `git revert` undoes it. #72 set 0.8 s the same way.
   - Why not wait for a 0.8 s block first, as #80's procedure says: the
     owner overrode that trigger. The reference instead is the baseline
     that exists, 3.2 % (3 of 94, #80's spec) to 3.9 % (4 of 102, the
     intent), counted by the same rule under longer holds. The thresholds
     stay #80's: **2 or fewer** fragment endings in a block of 50 `heard`
     lines is acceptable, **4 or more** is a cut-off. 3 is inconclusive
     and the next 50 lines decide.
   - **Rollback when cut-offs rise:** 4 or more in the first block of 50
     at `hold=0.60s` means the user sets `end_of_speech_seconds = 0.8` in
     `config.toml` that day (no rebuild, a restart of `omarchy-voice`; the
     config is read at start), and a one-line revert of the default follows
     as its own PR.
     The same block is then the trigger for decision 3.
2. **"Hold on after a trailing fragment" is not built now.** Its trigger is
   decision 3's. When it is built, the shape is fixed here, so that the
   follow-up does not rediscover it:
   - **Not "transcribe, then reopen the capture".** Closing `pw-record`
     (`listen_local.py:333-338`, a terminate and up to 2 s of wait), running
     whisper, and opening a new capture leaves a hole of teardown plus
     transcription plus startup. The words the user says in that hole are
     lost, and those are the start of the rest of the sentence. It would
     trade a cut-off for a clipped continuation. It also costs a second
     whisper pass on every fragment.
   - **The shape instead: transcribe at the hold without closing the
     microphone.** When `record_utterance` reaches the hold, it asks a
     caller-supplied `should_stop(pcm) -> bool` instead of breaking. The
     engine's version transcribes the clip so far and returns
     `not is_fragment(text)`. `pw-record` keeps writing into its pipe while
     that runs, so nothing is lost. If it stops, the transcript is the one
     `_hear` needs anyway, so a finished sentence pays no second pass: the
     wait moves from after the cut to before it. A fragment keeps
     capturing, up to one extra hold (a cap, so a user who really did stop
     on "and" is not held forever), and pays one more whisper pass over
     the longer clip. `is_fragment` moves from `tools/timing_report.py`
     into the package so the tool and the engine share one rule.
   - Cost, stated so the follow-up can check it: one whisper pass per
     fragment (the transcribe span in `TIMING`, today's p50 is unknown),
     plus a change to `record_utterance`'s signature, which
     `tools/bench_local.py --live` also calls. And it only catches the
     listed words. A clean-looking half sentence still ends the turn.
   - Why not now: at 3-4 % fragment endings, 96 turns in 100 would pay the
     new flow's complexity for nothing, and the 0.6 s block may show that
     no turn needs it.
3. **smart-turn v3 is deferred. Exact trigger:** 4 or more fragment endings
   in a block of 50 `heard` lines at any `end_of_speech_seconds` of 0.8 s
   or less, counted by `python3 tools/timing_report.py --since <day>` with
   `trace_timings = true`. That is #80's trigger unchanged, and decision 1's
   rollback condition is one instance of it. When it fires, a new intent
   weighs smart-turn against decision 2's shape. The cheaper one (decision
   2, no dependency) is the default choice unless the block's fragments
   are mostly clean-looking half sentences it cannot catch, which only the
   user, reading their own log, can tell.
   - Why not now: the new dependencies are the "real change to what the
     package is" that the intent's constraint names. `pyproject.toml`
     depends only on `mcp>=1.2` today, and `numpy` is not a dependency
     either. smart-turn would add `onnxruntime` (in nixpkgs,
     `python3Packages.onnxruntime` 1.27.1), `numpy`, a Whisper mel feature
     extractor reimplemented in numpy (not `transformers`, which the
     constraint forbids at run time), and 8 MB of int8 weights that are not
     in nixpkgs. All of that for a failure that has not been seen once at
     0.8 s.
   - Recorded for the follow-up, not decided by it: the weights are pinned
     in `nix/package.nix` with `fetchurl` and a hash from the Hugging Face
     revision, installed under `share/`, and never downloaded at run time.
     It is opt-in (`end_of_turn = "smart-turn"`, default `"hold"`). The
     numpy mel extractor is tested against a fixture of `transformers`'
     output, generated once and committed. The model runs once per pause at
     the hold, through the same `should_stop` seam as decision 2, so the
     two are alternatives behind one hook, not two hooks.
4. **The wake path follows the same hold. No separate knob.** `_wake_turn`
   passes `self.config.end_of_speech_seconds` (`local_engine.py:477-479`),
   so the default change reaches it with no code. Its failure is benign: a
   wake capture that ends after "Oma" and a thinking pause is heard as the
   wake word alone, which switches listening on (`:490`, `:498-499`), and the next
   turn at the same 0.6 s hears the instruction. That costs the user one
   repeat, not a wrong action. A wake knob (`wake_end_of_speech_seconds`)
   would be config for a failure nobody has reported. A test is added that
   pins the wake path to the same hold, so a future detector cannot quietly
   skip it or fork it.
5. **#128 stays separate.** This change touches no line of `_wake_turn`:
   `opened`, `capped` (`:478-482`) and the echo tail wait are untouched.
   #128 is about the cap window, not the hold, and it has its own fix (an
   "opened" stamp after the tail wait, see #80's plan). Folding it in would
   put an engine change into a change whose point is that it has none, and
   would make a rise in fragment endings harder to attribute. Note for
   #128: a shorter hold makes a one-breath wake capture shorter, so it is
   further from `wake_max_seconds`, not closer. The two do not interact.
6. **"Cut off" is measured by #80's `is_fragment` count, and nothing new.**
   It is a lower bound, but the thresholds in decision 1 are set against a
   baseline counted by the same rule, so the before/after comparison is
   like for like. The "user repeats within a few seconds" signal is
   rejected for now: it needs engine code that compares consecutive
   transcripts, which is new logic built without data, and it confuses a
   correction with a cut-off. **`trace_timings` is turned on on this
   machine now**, by the owner in `config.toml`, while this spec is in
   review. It is a manual step, not part of the diff. Whatever lines
   accumulate at 0.8 s before the merge are the before block, even if it
   is shorter than 50.
7. **CPU budget: decided when a detector is, with the bar fixed now.** It
   applies only to decision 2 or 3's follow-up. The bar: the added time per
   pause at p95, on each of p620 and razer, is under **a quarter of the
   hold it saves** (under 0.05 s against the 0.2 s from 0.8 to 0.6). A
   quarter, not "less than", so the detector costs clearly less than the
   plain hold it replaces. Measured by a bench over synthetic audio (her
   own voice, synthesized by the engine's TTS, and silence), never a live
   capture. For decision 2, the added time is the second whisper pass
   on a fragment turn. For smart-turn, it is the ONNX call.

## Design

Three lines of product change and the tests that pin them. Nothing is
added to `pyproject.toml`, `nix/package.nix`, `listen_local.py` or
`local_engine.py`.

1. **`src/omarchy_voice/config.py:361`**:
   `end_of_speech_seconds: float = 0.6`. Its comment (`:358-360`) gains "(#138; 0.8 s
   before)" so a reader of the config knows which value was tried first.
2. **`share/config.example.toml:89-91`**: the commented default becomes
   `# end_of_speech_seconds = 0.6`, and the comment says how to go back:
   "Set it to 0.8 if you get cut off mid-sentence."
3. **`tools/timing_report.py` docstring**: the procedure now reads "At
   0.6 s (the default since #138)". The step "if 0.8 s is acceptable, set
   0.6" becomes "if 0.6 s cuts off (4 or more in 50), set 0.8 in
   config.toml and file the revert". The thresholds are unchanged. No
   code in the tool changes.
4. **README.md:388** names `end_of_speech_seconds` without a value, so it
   is not edited. `docs/omarchy-voice.html` does not mention the hold.

Tests that assert the default move with it. Tests whose arithmetic only
uses the hold pin `end_of_speech_seconds=0.8` explicitly in `build(...)`,
so they keep testing what they tested and do not silently change meaning:

- `tests/test_config.py:183-184`: the default is `0.6`.
- `EndOfSpeechTests.test_a_turn_ends_on_the_local_hold`
  (`tests/test_local_engine.py:1708-1715`): `holds == [0.6]`. It asserts
  the default reaches `record_utterance`.
- `EndpointTests` (`:1488`): `assert_measured`'s `hold=0.8` and the tests
  that call it without a hold pin `end_of_speech_seconds=0.8` in `build`.
  `test_the_hold_is_in_the_line` already passes its hold.
- The `first-audio=1.80s` test (`:1433`): pins 0.8 in `build`.
- The plan re-checks every other test that reads the default through the
  `Room`'s hang (`:1153`) and pins it where the arithmetic needs 0.8.

New test, `EndOfSpeechTests.test_the_wake_turn_ends_on_the_same_hold`:
muted, `wake_word="oma"`, `record_utterance` patched as in
`test_a_turn_ends_on_the_local_hold`, `await session._wake_turn()`, and
`holds == [session.config.end_of_speech_seconds]` with a non-default value
(`end_of_speech_seconds=0.7`), so it proves the wake path reads the config
and does not only happen to equal the default. It passes on `main` today.
It guards decision 4, and the mutation below proves it.

## Alternatives rejected

- **A detector in the same change** (decision 1): the before/after could
  not be attributed.
- **Only this machine's `config.toml`** (decision 1): unreviewed and
  single-host.
- **Wait for a 0.8 s block of 50 first**: the owner overrode #80's
  trigger. The existing 3.2-3.9 % baseline is the reference.
- **0.5 s or lower**: #80's procedure steps in 0.2 s, and a 50 ms frame
  plus `--latency 20ms` is already 14 % of 0.5 s. One step at a time.
- **Reopen the capture after a fragment** (decision 2): it loses the
  words said in the hole.
- **smart-turn now, or `transformers` for its features** (decision 3):
  new runtime dependencies for an unseen failure, and `transformers` is
  forbidden by the intent.
- **A separate wake hold** (decision 4): config for an unreported failure.
- **Fold in #128** (decision 5): unrelated lines, and it muddies the
  measurement.
- **A "repeated within seconds" cut-off signal** (decision 6): new logic
  without data, and it counts corrections as cut-offs.
- **Silero VAD and the LiveKit turn-detector**: rejected in #80's spec,
  for the reasons the intent restates. Not reopened.

## Risks

- **0.6 s cuts off a thinking pause.** That is the experiment. It is
  bounded: at most one block of 50 turns before the count says so, and
  one config line undoes it on the day. Every cut-off costs the user a
  repeat of the rest of the instruction, which then arrives as its own
  turn. A half instruction can still be acted on (for example "turn it
  down" when "…to thirty" was coming). That risk exists at 0.8 s too, and
  #86's consent checks are unchanged.
- **The count is a lower bound.** Clean-looking half sentences are missed
  before and after alike, so a real rise in them is invisible. The owner,
  who is also the user, will notice being cut off before 50 lines, and
  the rollback does not need the count.
- **Blocks cross the change.** The report's `--since` is a day, so a block
  that starts on the day of the change mixes holds in the `heard`
  section. The `endpoint` section is grouped by `hold=` and is not mixed.
  The protocol below starts the after block on the day after the rebuild.
- **The before block may be small or empty.** If the owner does not speak
  to it at 0.8 s with tracing on before the merge, the before is the old
  3.2-3.9 % baseline alone. Stated, not hidden.
- **Wake cut-offs are not in the count.** A wake capture that ends after
  "Oma" logs `wake    heard`, which the report's `heard` pattern
  (`  heard   `) does not match. A one-breath instruction that is acted on
  goes through `_answer` and is counted (`local_engine.py:568`). Wake
  cut-offs are benign (decision 4), so this is accepted.
- **No host risk beyond the hold.** p620 and razer get 0.6 s on their next
  rebuild. A host with `end_of_speech_seconds` set in `config.toml` keeps
  its value.

## Verification

Fakes only. No test records, plays audio or reaches D-Bus. Clocks are the
stepped fake from `SteppedRoomCase`; no assertion waits on real time.

Tests written first. They must **fail on `main`**, except the wake test,
which guards and is proven by mutation:

1. `test_config`: default is `0.6` (main: 0.8).
2. `test_a_turn_ends_on_the_local_hold`: `[0.6]` (main: `[0.8]`).
3. `test_the_wake_turn_ends_on_the_same_hold`: `[0.7]` with
   `end_of_speech_seconds=0.7`.
4. `EndpointTests` and the `first-audio` test, with 0.8 pinned, pass on
   both `main` and the change: they no longer depend on the default.

Mutation checks. Each one alone, run the named tests, revert:

- D1: default back to `0.8` → tests 1 and 2.
- D1b: remove the explicit `end_of_speech_seconds=0.8` pin from one
  `EndpointTests` case, with the default at 0.6 → that case red. This
  proves the pin matters, and so that those tests no longer depend on the
  default.
- D4: in `_wake_turn`, `hold = 0.8` instead of the config → test 3.
- D2, D3, D5, D6 (nothing built): `git diff main --stat` lists only
  `config.py`, `share/config.example.toml`, `tools/timing_report.py`
  (docstring), `tests/test_config.py` and `tests/test_local_engine.py`,
  and `git diff main -- pyproject.toml nix/ src/omarchy_voice/local_engine.py
  src/omarchy_voice/listen_local.py` is empty.

Runners, with `DBUS_SESSION_BUS_ADDRESS=unix:path=/nonexistent` exported:

- `nix develop -c python3 -m pytest -q`: all pass, count N + 1 (N at
  `be27af4`, recorded by the plan's first step).
- `nix develop -c python3 -m unittest discover -s tests`: same count.
- `nix flake check --no-write-lock-file`: passes.

**Before/after protocol**, on real turns, read-only, with #80's report.
It proves the outcome or refutes it. It is not part of the merge gate:

1. Before (now, during review): `trace_timings = true` in this machine's
   `config.toml`. Normal use. On the merge day,
   `python3 tools/timing_report.py --since <day tracing went on>` gives the
   0.8 s block: `endpoint` p50/p95 under `hold=0.80s`, its overshoot, and
   fragment endings k of n.
2. After: rebuild. From the next day, `--since <that day>`, run the report
   once 50 `heard` lines exist. Read `hold=0.60s`'s endpoint p50/p95 and
   overshoot, and the fragment count.
3. Judge: the endpoint p50 is about 0.2 s lower at `hold=0.60s` than at
   `hold=0.80s` (the overshoot should be the same, since the teardown did
   not change). Fragment endings: 2 or fewer keeps 0.6 and closes #138. 3
   runs one more block. 4 or more is decision 1's rollback, and decision
   3's trigger: a new intent for a detector, with these two blocks in it.
4. The report prints counts only. Nothing heard is copied into the issue,
   the PR or any artifact.
