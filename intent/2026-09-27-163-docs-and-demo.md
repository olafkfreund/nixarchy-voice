# Intent: A published page, a real demo, and a story a new user can follow

## Problem

Actions and routines (#158), the terminal fix (#161) and uptime from `/proc`
(#162) are merged and deployed on p620 and razer. Nothing a user reads says so.

**nixarchy-voice's own page is not published.**
- GitHub Pages is configured (`build_type: workflow`, a `github-pages`
  environment), but no workflow deploys it. The only workflow,
  `.github/workflows/check.yml`, has no Pages step, and
  https://olafkfreund.github.io/nixarchy-voice/ returns 404.
- The only page, `docs/omarchy-voice.html` (735 lines), is upstream's 0.3
  page. It says "8 tools", "113 unit tests" and "Omarchy 4.0.1", and installs
  with `./install.sh`, which does not exist in this repo. It has no word on
  actions, routines, the menu, or the terminal behaviour.

**There is no media.**
- Not one screenshot, screencast or GIF is in the repo, and there is no
  recording script.
- A new user cannot see what Oma does before installing a ~1 GiB feature and
  signing a model account into it.

**There is no single "what it is and how I set it up" story.**
- It is spread across the README intro (1-30), Install (74-466) and Use
  (467-648).
- The README is also stale on the terminal:
  - 571-581 describe typed keys and the old "any pane you can see" rule;
    since #161, commands are pasted into Oma's own tmux session and the
    exit status is read;
  - 602 has the same gap in the tool table;
  - 599 and 859 do not mention that uptime is now answered.

**nixarchy still describes the old plugin.**
- It pins nixarchy-voice at `647f9e5`, which predates all three changes
  (`flake.nix:226-230`).
- `docs/manual/plugins.md:40` lists Voice as "**opt-in, coming**".
- The section at `plugins.md:388-408` ends "*Not recorded yet*".
- The size claims disagree: "about 1 GiB" at :403 against 6.7 GiB in
  `data/apps.nix` and `modules/nixos.nix`.
- `docs/index.md:90`, `README.md:470` and `docs/llms.txt:115` repeat the
  "coming" status.

## Proposed outcome

1. **A published project page** at https://olafkfreund.github.io/nixarchy-voice/,
   built from this repo and deployed on every push to `main`. It covers:
   - what Oma is;
   - what it does, including actions and routines;
   - how to set it up;
   - what it costs;
   - what it will and will not do (the safety model);
   - the demo and screenshots.
2. **A user story**, the path a new person actually takes:
   - install (Home Manager, or nixarchy's *Set up voice*);
   - the key, or the bar widget;
   - the first thing to say;
   - a first action, and a first routine;
   - where to look when something does not work.

   This lives in the README (a "Getting started" section at the top) and on
   the page, from one source of truth.
3. **A screencast with sound, recorded on razer,** not on the user's work
   desktop. Oma is heard answering. It shows:
   - a spoken or typed request;
   - an action made by asking;
   - the action run from the Voice ▸ Actions menu;
   - a routine's notification;
   - a terminal command whose failure is reported.
4. **Screenshots:** the Voice ▸ Actions menu, a routine notification, the bar
   widget, and a readback-and-confirm.
5. **The README brought up to date** with #161 and #162.
6. **nixarchy updated, in its own repository and under its own workflow**,
   once the media exists:
   - the pin bumped to current nixarchy-voice;
   - the Voice section rewritten with actions and routines, and linking the
     page;
   - silent GIFs and stills in nixarchy's formats;
   - the status and size claims made true in every place they appear.

## Affected users and systems

- **nixarchy-voice:** `README.md`, `docs/`, a new Pages workflow, a new
  demo/recording folder (scripts plus media), and `HANDOFF.md` where it is
  stale.
- **razer:** the recording host.
  - Oma's chain works there: whisper.cpp → Claude Code on the user's plan →
    Piper "Jenny".
  - There is no ElevenLabs key there, and desktop control is off.
  - `grim`, `gpu-screen-recorder`, `ffmpeg`, `pw-record` and `ai-mirror` are
    installed.
- **nixarchy** (`/mnt/data/Source-home/nixarchy`), a separate repo with its
  own rules (`docs/AGENTS.md`, CI checks):
  - `docs/manual/plugins.md`, `docs/index.md`, `README.md`, `docs/llms.txt`,
    `docs/img/…`, `flake.nix`/`flake.lock`, and the size figures in
    `data/apps.nix`/`modules/nixos.nix` if the fix lands there.
- **Readers:** anyone deciding whether to turn Voice on.

## Constraints

- **Record on razer, never on p620.** p620 is a work desktop with client
  sessions and credentials on screen. Nothing private may appear: no real
  mail, no work repositories, no tokens, no notifications from real people.
- **What is shown must be real.** Every feature in the demo runs for real,
  with no mock-ups and nothing staged to look like it worked. A step that
  fails on camera is fixed or cut, never faked.
- **The screen-recording guard (#52) stays on.** `read_screen` refuses
  while a recorder runs, so the demo shows actions, not screen reading. It
  is not switched off for the camera.
- **nixarchy's rules apply to anything landing there:**
  - GIFs: 4 fps, 900 px, under 1 MB, via `tests/demo/encode-gif.sh`;
  - stills: 16:10 whole desktops; video: 16:9;
  - the sidebar nav, `llms.txt` and `manual/index.md` must agree;
  - a status must change in every place it is claimed;
  - Voice gets **no** `<!-- id -->` in the plugin table, since it is not in
    `defaultPluginSet` and CI fails both ways;
  - CI-gate edits there need a human.
- **Adding a Pages workflow here is a new CI file,** so it is called out in
  the PR for review.
- **Size limits:** the repo should not grow by tens of MB. Large video goes
  to a release asset or is compressed; the page links it.

   `docs/index.html`, keeping its design and replacing its 0.3 content, or
   switch to Markdown/Jekyll like nixarchy? **Recommended:** keep the one
   static HTML page (no generator), deployed by a small Pages workflow.
4. **Where the video lives.** In the repo (compressed, a few MB) or as a
   GitHub release asset? **Recommended:** a compressed mp4 in the repo if it is
   under ~8 MB, else a release asset.
5. **nixarchy scope.** Besides the docs, should this also bump nixarchy's
   nixarchy-voice pin, and change "opt-in, coming" to "opt-in", now that the
   *Set up voice* row exists? And should the 1 GiB / 6.7 GiB sizes be settled
   by measuring? **Recommended:** yes to all three, as one nixarchy issue
